# 剪映 11.5 位置动画最小复现

本实验比较仅有 X 曲线的动画与显式补齐恒定 Y 曲线的对照。工具生成无版权依赖的纯色素材、两份原生计划和参数清单，并对已经完成的导出做逐帧测量。工具不调用原生引擎、不登记草稿、不访问网络，也不修改 engine。

## 修复和离线回归

导出会先核对 build 与已安装引擎的精确 profile，跨版本组合在创建导出目录前拒绝。只有 `jy14-headless-macos-11.5.0` 暂存副本中的 video／text 片段，同时满足存在 `KFTypePositionX`、缺少 `KFTypePositionY`、静态 Y 非零，才增加恒定 Y 曲线。两端分别位于片段局部 0 和 `target_timerange.duration`；片段在主时间线上的开始位置不叠加到端点。原 X、已有 Y 和其他曲线均保持不变；重复补全不会生成第二组 Y。

复合导出先验证冻结 build 的原 sidecar，再在内嵌时间线上生成一次曲线。所有层级的外部 wrapper 复用相同曲线及 ID，仅更新对应片段的 `common_keyframes`；保留 wrapper、子时间线的未知字段及配置。原来已有的曲线若与内嵌表示不一致，导出拒绝继续，不通过覆盖来掩盖差异。完成路径重定位和 sidecar 写出后，才记录最终大小和哈希，并比较每份表示的内容、轨道／片段顺序和完整关键帧 ID／顺序。原生导出结束时再次检查这些文件。11.4.2 暂存不补曲线，复合草稿首页登记限制保持原状。

运行不需要剪映或 codec 的结构回归：

```bash
python3 -m unittest discover -s tests -p test_position_staging_115.py -v
```

测试直接调用正式 `stage_timeline`，另在 `run` 的原生边界替换运行身份读取，验证跨 profile 在暂存之前拒绝；后者不算作原生验收。合成视频 fixture 在这组结构测试中是不可解码的不透明占位字节，只用于检验素材复制和清单，不会传给原生引擎。覆盖正负 Y 的 video／text、延后开始、原曲线保持、幂等、多片段 ID、一／两层复合 sidecar、未知字段与配置、文件篡改、曲线重排和旧版本。

生成器仍拒绝把关键帧与裁剪／变速计划组合。已有草稿的导入和冻结导出路径能够保留这类组合：基本结构验证不会排除非零 `source_timerange.start` 或固定 `speed`，只禁止未经验证的曲线变速。对这类输入，常量 Y 不改写已有 X 点或源时间范围；其实际原生时间覆盖不能由本页普通 2 秒样本推断。9/22 已取得八种组合的独立原生时间函数与画面对照，见[时间映射证据](evidence/time-mapping-115.json)和[验收状态](COMPATIBILITY-115-ACCEPTANCE.md)。普通视频固定速度的原生偏移使用源时间；本补交只更正相应源码注释，未开放生成器或修改导入 X 的偏移。

## 固定实验参数

| 项目 | 参数 |
| --- | --- |
| 输入 | 128 × 72，cyan，H.264/yuv420p，无音轨，30 fps，2 秒 / 60 帧 |
| 时间线 | 640 × 360，30 fps，2,000,000 微秒，一个 video 轨道，一个连续片段 |
| 变换 | scale = 0.2，静态 x = −0.7，静态 y = 0.4 |
| A | X 线性关键帧：0 微秒为 −0.7，2,000,000 微秒为 0.7；没有 Y 曲线 |
| B | 同一素材和业务参数；额外的 Y 关键帧在 0 和 2,000,000 微秒均为 0.4 |
| 背景 | 原生画布未覆盖区域，预期为黑色；不添加背景轨道 |

A、B 计划除了草稿 name 和 Y 曲线，内容完全一致。最后一帧的时间为 59/30 秒，并不采样 2 秒处的最后一个关键帧。生成物使用本次输出目录解析出的绝对素材路径；`fixture.json` 同时保存使用相对素材路径的可移植计划规格、素材 SHA-256、实际生成命令、探测结果和工具版本。不同 ffmpeg 版本的 H.264 字节不保证一致，因此必须记录并复用本次同一份素材。

## 生成

需要 Python 3.9+，以及 PATH 中可用的 ffmpeg（含 libx264）和 ffprobe；没有 NumPy 或 Pillow 依赖。在仓库根目录执行：

```bash
python3 tools/reproduce_position_115.py generate --out "$PWD/work/position115-fixture"
```

输出目录必须不存在。文件包括 `cyan-source.mp4`、`a-x-only.plan.json`、`b-explicit-y.plan.json` 和 `fixture.json`。生成失败时保留部分文件供排查；重试使用新目录。

## 原生实验边界

生成完成不表示原生缺陷已经复现。必须使用同一固定源码基线、剪映 11.5 build、官方库、codec 和导出参数分别 build / verify / export A、B，并记录各自退出状态及日志。构建与导出命令使用仓库 [README](../README.md) 中的公开入口；独立导出不需要先登记首页。保留 build manifest、verify 结果、export audit、两份原片和本工具的 JSON 报告。

第一阶段可先测未修复 A，确认当前基线是否还出现问题；B 是显式曲线对照，不能当成自动修复完成的证据。后续阶段再用同一个 A 计划验证自动修复，并补齐复合片段和保存回读检查。本工具的稳定结果只证明当前输入文件符合固定像素检查，不代替整个兼容修复 PR 的验收。

## 测量

```bash
python3 tools/reproduce_position_115.py measure \
  --video "$PWD/work/position115-a-export/render.mp4" \
  --out "$PWD/work/position115-a-measurement.json"
```

`--out` 必须是尚不存在的 JSON 文件，其父目录必须存在。工具通过 ffprobe 遍历视频帧并计数，通过 ffmpeg 解码完整 RGB24 帧序列，不截取前几帧、不调整帧率、不缩放画面，也不自动旋转画面。每帧报告时间戳、cyan 像素数、包含两端的 `[x_min, y_min, x_max, y_max]` 边界框，以及边界框中心 X/Y。中心计算使用像素索引，因此可以出现半像素值。

以下阈值固定在源码与生成 manifest 中，不因测量结果而调整：

- cyan 匹配条件为 R ≤ 80、G ≥ 150、B ≥ 150，三项同时满足，边界值包含在内。
- 必须恰好解码 60 帧，ffprobe 计数也必须为 60；每帧尺寸为 640 × 360，标称帧率 `r_frame_rate` 严格为 30，时间戳从 0 起逐帧匹配 `index / 30`，容差为 0.00001 秒。
- 原生文件时长可能按微秒量化，例如 60 帧、时长 1.999998 秒会报告 `avg_frame_rate = 30000000/999999`，约 30.00003。平均帧率的允许区间仅由既定时间容差推导：`60 / (2 + 0.00001) ≤ avg_frame_rate ≤ 60 / (2 − 0.00001)`，以有理数比较，不另设帧率误差或扩大时间、Y 阈值。上述微秒量化案例通过；平均帧率 30.001 或标称帧率不等于 30 仍失败。
- 每帧必须有 cyan；缺失颜色会记录帧号并失败，不能通过只计算剩余帧来掩盖问题。
- X 中心必须逐帧不减，且首尾位移大于 1 像素。任何负向步进都会失败，静止画面也不能通过。
- 所有帧 Y 中心的最大值减最小值必须 ≤ 1 像素，才判定稳定。
- 奇数帧、偶数帧分别满足 Y 跨度 ≤ 1 像素，且两组均值相差 > 1 像素时，记录 `two_level_alternation: true`。另记录超过 1 像素的连续 Y 位移反向次数，供判断更复杂的抖动；这些信息不改变稳定性阈值。

返回码为 0（`stable`，所有检查通过）、1（`failed`，完整报告列出失败项）、2（`error`，输入或工具运行错误）。Y 不稳定、缺帧、无颜色、解码报错或 X 运动不符均不能返回 0。脚本参数错误同样返回 2。此测量针对已知的纯色最小场景；不要用它证明任意真实项目的视觉正确性。

## 2026-09-20 本机验收与边界

使用固定上游 `bbc46d3` 的业务代码、精确剪映 11.5.0 库，以及单独记录的本机 codec 适配进行对照。原生 C++ 导出器、引擎身份、输入和参数在各组中一致；codec 适配未包含在兼容补丁中，这不等同于上游原样环境验收。

- 未修复 A：60 帧全部解码，Y 在 107.5／251.5 像素之间交替。
- 显式 Y 对照与自动补齐候选：各 60 帧，所有逐帧 X/Y 中心相等，Y 恒为 107.5；有效暂存参数一致。
- 19 秒平面矩阵及其单层复合副本：均为 570 帧，六个有效区间各 60 帧。负 Y、正负 Y 文字、已有 Y 动画、无 X 和零 Y 对照全部通过预设测量；210 个空白帧无误检对象。
- 双层复合副本：本次看到最深子时间线丢失并输出纯黑；相同 build 在未修复上游也出现该丢失。9/21 后续诊断将首个丢失边界进一步定位到原生解析，根级定义登记的诊断修正成功，正式构造／编辑／sidecar 尚未修复，见[最新验证状态](VERIFICATION.md)。两层 sidecar 的结构与哈希一致不构成深层原生渲染支持承诺。原失败任务的 569／570 帧问题另行保留，没有放宽计数或自动重试。
- 手工导入的裁剪／固定变速样本：自动与显式 Y 的 120 帧位置完全一致，Y 全程稳定；手工设定的 X 局部时间偏移在原生中没有产生预期的完整运动。因此只证明该样本的恒定 Y 等价，不能宣称验证了导入 X 的时间映射，也不能把手工构造的假设当作已有合法草稿的缺陷。生成器的原有限制保持不变。

上述失败和有限结论均需随原始成功证据保留；`encoded-and-decoded` 仍不代表复合内容或运动轨迹正确。原生保存持久化能力与冻结导出分开验收，复合草稿首页登记继续被禁止。
